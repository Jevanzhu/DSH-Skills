# 单包正本（设计方案）

- 定位：本档回答「两个 skill 为什么合回一个、哪些约束随之消失、哪些换了形态」。**不属于本档**：技能正文、references 与门禁逻辑的内容改动（本批一字未改，只有路径与措辞）。
- 来源：整合版批次（`81b5ca8`）确立的「构建镜像」形态，与仓主「只装一个、不再装两个」的诉求。
- 判据：与 DSH 适配、整合版同形——「去掉客户端专名后仍然成立」；判据不因合并而放宽。

## 一、目标形态

`skills/dsh-project-harness/` 是仓内唯一的 skill：`SKILL.md`、`references/`、`scripts/`、`templates/` 全部是真身，没有任何目录由构建生成。安装面只有一个副本，客户端里只有一个技能条目。

## 二、决定清单

**一、两源退役，包内文件转正。**

- 结论：删除 `skills/agent-notes` 与 `skills/project-harness`；资源逐字节并入本包成为正本，`SKILL.md` 继续是合并叙述的门面。
- 最强替代：保留两源 + 构建镜像（整合版原形态）。否决理由——镜像让同一份文件住两处，每次资源改动都要多跑一步构建，而「装两个」的表象仍留在仓库里。
- 次强替代：保留两源、只发布整合版。否决理由——发布面之外仍是三份目录，维护者仍要判断改哪一份；仓主要的是「一个 skill」，不是「一个安装包」。

**二、构建器与逐字节门禁退役。**

- 结论：删除 `scripts/build-integrated.ts` 与其 spec；从 `scripts/structure.spec.ts` 删除「整合版镜像逐字节一致」与「共享文件跨 skill 一致」两条测试。
- 最强替代：保留 `--check` 当守卫。否决理由——没有源就没有镜像，`--check` 的自变量消失，留着等于让门禁去测一个永久为空集。
- 次强替代：改成「包内无重复文件」。否决理由——同一路径在一个目录里不可能有两个文件，这条断言在文件系统层面恒真。

**三、spec 随迁，不再排除。**

- 结论：11 份 spec 迁入本包 `scripts/`，与门禁脚本同目录；`package.json` 的 test 列表只指本包。
- 最强替代：继续排除 spec。否决理由——排除的理由是「spec 断言两源布局」，但那只是一份 `bootstrap.spec.ts` 里的两个用例；其余十份测的是门禁逻辑本身，排除会让 270 例掉到几十例，负向对照纪律失去落点。
- 次强替代：spec 迁入独立目录。否决理由——spec 与被测脚本同目录是既有约定，`node --test <dir>/*.spec.ts` 与相对 import 都靠它。

**四、bootstrap 去掉跨目录回退，前置检查保留。**

- 结论：`AGENT_NOTES_SKILL` 三元回退删除，type import 改为 `./aliases.ts`；`VERIFIER_FILES` 从「文件名 + 源目录 + paired」三元组简化为文件名数组，前置检查改为「本包 `scripts/` 缺任一校验器即拒绝」。
- 最强替代：保留回退逻辑（在单包下恒为真）。否决理由——恒真的分支是死代码，且「兄弟目录」这个概念已从仓库消失，留着会让读代码的人去找一个不存在的布局。
- 次强替代：删除前置检查。否决理由——`run-gates.ts` 调用每一个校验器，缺文件时目标仓库装的是一套 `MODULE_NOT_FOUND`；负向对照要求「缺文件必须拒绝，且不留半成品」。

## 三、边界与诚实声明

前半段是重组，不是重写：`SKILL.md` 正文、references、templates 与门禁逻辑的内容一字未改，改的只有路径、`<skill-dir>` 示例与「两源」措辞。测试从 281 例降到 270 例，缺少的 11 例全部是布局专属：构建器 spec 七例、结构守卫两例、`bootstrap.spec.ts` 的三例合并为一个「副本不完整」用例。

合并并没有减少任何判据：门禁判什么、什么时候红、负向对照强制，全部原样。它减少的是目录数与安装步骤。

## 四、重访条件

- workbuddy 实测仍待办（活账）；合并形态没有改变这条的验证方式。
- 若将来出现「只想要决策记录、不要治理门禁」的采用方：拆回去的成本是重新引入构建器与两源。届时先确认「两个技能条目」是否真是对方客户端的硬约束，再动手拆——不要因为某个采用方习惯了两份目录就回退本决策。
