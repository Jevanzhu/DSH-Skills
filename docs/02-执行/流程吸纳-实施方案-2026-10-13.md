# 流程吸纳 执行方案

- 定位：执行正本——批序、每批的靶点与验收、执行记录（末节回填）。**设计理由不在本档**，正本 = [流程吸纳-设计方案-2026-10-13.md](../03-设计/流程吸纳-设计方案-2026-10-13.md)。
- 关系：设计档定族、边界与理由；本档只回答「谁先谁后、每批动什么、怎么算过关」。
- 全局序：**批 1 文档治理 → 批 2 注释卫生 → 批 3 测试纪律 → 批 4 对账与发布 → 批 5 agent 工作纪律**。收口条件统一，见设计档 §六：负向对照齐、规则与文档同批、`npm test` 全绿、链上同步记档。

## 批 2：注释卫生（已完成）

- 靶点：注释只写约束与语义、修复史归 git；两族判据（标签形态与切除残形）缺一不可；字面量红线（字符串／模板／正则永不报告）；例外与承重锚注的显式登记；扫描面 fail-closed 且不入台账。
- 动作：`verify-comment-hygiene.ts`（逐字符状态机读注释面、台账接入）＋ 负向对照 21 例 ＋ `references/comment-hygiene.md`；接线 `run-gates`（doc-quick 第 5 条）／`bootstrap`（复制校验器、按实测目录植入起始规则、并入台账家族）／本仓 `check` 聚合（原 `check:docs` 更名，现含四道文本门）／本仓自用 manifest。
- 验收：21 条对照全绿；本仓 26 档、6 形态全绿；字面量反例在 spec 内钉死；门在本仓先行红过两处（示例注释写了具体日期），按判据改为占位符后转绿。

## 批 3：测试纪律（已完成）

- 靶点：表面绿而覆盖消失（`.only`、无条件 `.skip`）的形式判据；先判该不该写（一条改动 = 一条回退即变红的用例、断言只锚可观察面、并入优先、分层执行）；数字与清单的口径纪律（静态可复现、来源单一、从代码面取、宣称值失准即红、顺序快照）。
- 动作：抽出共享扫描器 `surface.ts`（注释面 + 代码面，一处实现，注释门与测试门共用）＋ `verify-test-hygiene.ts`（`.only` 一律红；`.skip` 首参为标题字面量或 `true` 即红，条件式环境门合法）＋ 负向对照 16 例 ＋ `references/test-reliability.md` 扩三节（该不该写 / 表面绿而覆盖消失 / 数字与清单）＋ 接线 `run-gates`（文本门组更名 textGates，doc-quick 第 6 条）／`bootstrap`（复制校验器与共享扫描器、按实测目录植入测试面、并入台账家族）／本仓 `check` 与自用 manifest。
- 归属调整（结论）：**账实对照的门禁形态与批 4 的「宣称数字可核」是同一机制**（一条宣称 = 文档里的数字 + 一条从源头测它的命令），故并入批 4 一起落，避免造两个半成品门；本批已把它的全部判据（静态口径、单一声明点、勿引入平台差值锚、从代码面取数）写入 `test-reliability.md`，并交出取数用的代码面扫描器。
- 验收：16 条对照全绿；本仓 8 档测试面全绿；真仓对照——临时加一条 `test.only` 即红（报出档:行与原文），还原后绿。

## 批 4：对账与发布（已完成）

- 靶点：文档宣称的数字可核（一条宣称 = 数字或清单 + 源头命令，失配即红；含批 3 归属过来的账实对照）、门禁下限规则（「只增不减」的机器形态）、发版批纯度（先给出可判形态，给不出就只作评审判据）、阈值单一声明点。
- 动作：`verify-doc-claims.ts`（`count` 与 `list` 两类宣称；命令是 argv 数组、以仓库根为 cwd 运行；`atLeast`／`atMost` 表达下限与上限；**有意不挂台账**——改一个错数比记一笔错账便宜）＋ 负向对照 17 例 ＋ `references/gates.md` 补「宣称值：不自己更新，就让门禁去对账」（三条纪律与诚实边界）与 `governance-model.md` 补「发版批纯度」＋ 接线 `run-gates`（doc-quick 第 10 条）／`bootstrap`（复制校验器、植入空 manifest 与提示，**不入台账家族**）／本仓 `check` 与自用 manifest（两条宣称：doc-quick 门禁数下限、`skills/` 目录清单）。
- 验收：17 条对照全绿；本仓两条宣称绿；真仓双红对照——从门禁表摘掉一门，下限宣称即红（报出「文档说 10，源头测到 9」）；临时新建 `skills/_demo/`，清单宣称即红（报出文档未提及的项）；两处还原后绿。CI 步骤名原先逐个枚举文本门，加门即漂移，现改为指回 `npm run check`——单一声明点的落地。
